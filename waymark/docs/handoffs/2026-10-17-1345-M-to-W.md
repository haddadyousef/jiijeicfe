### 4.1 Project Sidewalk (Seattle) — checked Sat 13:00 via public web fetch
- **Seattle server:** `https://sidewalk-sea.cs.washington.edu`.
- **Endpoint:** `GET /v3/api/labelClusters` works with **no API key**.
  - Tested: `?bbox=-122.3080,47.6520,-122.3020,47.6560&inline=true` (University District, next to campus).
  - It returned GeoJSON `Point` features.
- **bbox order is longitude first** (`minLng,minLat,maxLng,maxLat`). The design doc's §7.1 bundle `bbox` is written lat-first, so the pipeline must convert, or the bundle schema should say which order it uses.
- **Query params** (from the docs page):
  - Location and filtering: `bbox`, `regionId`, `regionName`, `labelType` (comma list).
  - Raw labels and cluster size: `includeRawLabels`, `clusterSize`.
  - Dates: `avgImageCaptureDate`, `avgLabelDate`.
  - Severity: `minSeverity`, `maxSeverity` (1–3).
  - Output: `filetype` (`geojson` | `csv` | `shapefile` | `geopackage`), `inline`.
- **Real `properties` fields:** `label_cluster_id`, `label_type`, `street_edge_id`, `intersection_id`, `osm_way_id`, `region_id`, `region_name`, `avg_image_capture_date`, `avg_label_date`, `median_severity`, `agree_count`, `disagree_count`, `unsure_count`, `cluster_size`, `label_ids`, `users`, `tag_counts`, and `labels` (only with `includeRawLabels=true`).
- **Severity is 1–3**, not 1–5 as §7.1 says.
- **Privacy:** `users` holds labeler UUIDs. Drop it in P2; it should never enter the bundle.
- **Label types:** `CurbRamp`, `NoCurbRamp`, `Crosswalk`, `SurfaceProblem`, `Obstacle`, `Signal`, `NoSidewalk`, `Other`.
  - Suggested mapping to the doc's open enum: `NoCurbRamp→missing_curb_ramp`, `CurbRamp→curb_ramp`, `SurfaceProblem→surface_problem`, `Obstacle→obstacle`, `NoSidewalk→no_sidewalk`, anything else → `other`.
  - `Crosswalk` and `Signal` don't exist in the doc's enum. Your call whether to keep them, possibly as positive crossing info later.
- **Density sample:** that one small bbox returned **66 clusters**: 37 CurbRamp, 10 SurfaceProblem, 9 NoCurbRamp, 8 Obstacle, 1 Crosswalk, 1 Other.
- **Imagery age:** the first features had `avg_image_capture_date` 2019-05 and `avg_label_date` 2019-07. So staleness is real and the verification loop has something to do.
